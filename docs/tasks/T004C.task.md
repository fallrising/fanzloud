# Outcome

Retrieve one provider-managed task diff through the pinned trusted runner and return only the
bounded untrusted `CloudDiff` projection without applying it locally.

# Inputs

- TD §§2.3 INV-007 and INV-011, 8.2–8.10, 11, 14, and 15.0
- ADR-0002
- Accepted T003 and T004A

# Deliverables

- Fixed diff execution over an accepted task reference.
- E0 success/failure snapshot tests and bounded draining.
- Redaction, no-apply, no-checkout, and no-artifact-publication tests.
- Proof that T004A's validated diagnostic sentinel prevents the pinned upstream write.

# Non-scope

Patch parsing, application, semantic path validation, repository checkout, artifacts, status
polling, backend conformance, and browser rendering.

# Invariants

- Diff text is untrusted display data and is never executed or applied.
- No local repository, workspace, credential, prompt, or raw diagnostic is returned.
- The child cannot claim E0 while a failure can mutate observable local state.

# Dependency Evidence

Blocked until T004A and T004B are Accepted.

# Specification

Normative contract: [`SPEC-T004C`](../specs/SPEC-T004C-cloud-diff-retrieval.md).

# Machine Acceptance

Run every named SPEC-T004C E0, bound, fault, redaction, and no-local-application test plus the
workspace gates.

# Risks and Gaps

The pinned upstream Cloud client attempts to append `error.log` during backend initialization.
T004A must first install and revalidate a private `error.log/` directory sentinel so that the exact
pinned append cannot create or mutate a file. ADR-0003 defines the E0 snapshot over provider-task
and Codebox-managed state without reading provider-owned credential bytes. A version change reopens
the write assumptions for review.
