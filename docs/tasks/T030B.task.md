# Outcome

Implement bounded, ordered E0 replay of committed durable events after a caller-supplied sequence.

# Inputs

TD §§4.4–4.6, 7.2, 8.1–8.10, 11.1–11.4, 14, and accepted T030A.

# Deliverables

`load_after` with typed limit/corruption/storage errors and empty, one, many, limit, order,
cross-stream, restart, and no-mutation tests.

# Non-scope

Append, snapshots, live fanout, web frames, upcasting, or reducer application.

# Invariants

Replay returns only the named stream, only sequences greater than `after`, in strict ascending
order, without mutating the database.

# Dependency Evidence

Blocked until T030A freezes and accepts the version-1 SQLite event-row codec.

# Decomposition

One E0 `CU-EVT-02` boundary.

# Machine Acceptance

Focused event-store replay tests plus all workspace gates.

# Required Documentation Updates

Create `SPEC-T030B`, traceability, rustdoc, handoff, and `ACCEPT-T030B`.

# Risks and Gaps

Replay limits and corrupt-row handling require bounded `[NEW-SPEC]` details but no unresolved
security, atomicity, retry, or recovery decision currently blocks specification after T030A.
